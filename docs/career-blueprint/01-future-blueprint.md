# 1. 未來藍圖

## 最終目標

未來半年不是單押一家公司，而是建立一套可以重複使用的面試能力，再依不同公司補上少量專項準備。

主要目標分成三條職涯路線、四家公司：

1. **衝刺天花板：Amazon**
   - 目標角色：Front-End Engineer，或以前端為主的 Software Development Engineer。
   - 職涯價值：建立大廠等級的解題、系統設計、行為面試與國際履歷。
2. **追求 Remote 與國際薪資：Binance**
   - 目標角色：Frontend Engineer / Senior Frontend Engineer。
   - 職涯價值：累積全球協作、即時資料、交易產品與高效能前端經驗。
3. **在地穩健高薪：台積電、聯發科**
   - 目標角色：IT Front-End Developer、Web Front-End Engineer，或前端導向的 Software Engineer。
   - 職涯價值：進入台灣大型科技企業，累積企業系統、開發者工具與跨部門協作經驗。

## 現在的位置

- 約五年前端工作經驗，目前以中階前端工程師定位。
- 既有工作經驗能證明曾在 production 環境交付，但不能直接等同於能通過大廠面試。
- 過往薪資包含產業溢價；下一階段要讓薪資建立在可轉移、可驗證的工程能力上。
- JavaScript、TypeScript、框架與產品開發經驗可以保留，但資料結構與演算法已久未準備，需要重新學習，而不是只維持手感。
- 英文已有固定聽力練習，接下來需要增加技術口說、專案說明、Live Coding 口述與行為面試輸出。

## 核心策略：共同能力加公司專項

準備方式採用 **共同核心 70% + 公司專項 30%**。這不是面試題型的固定占比，而是個人的時間配置原則。

### 共同核心

四家公司都能使用的能力：

1. 資料結構與演算法基礎。
2. JavaScript、TypeScript 與瀏覽器底層。
3. React、元件架構與狀態管理。
4. 前端系統設計。
5. 效能、測試、安全、CI/CD 與可觀測性。
6. Production 專案的技術決策與成果證據。
7. 中文與英文的技術表達、行為面試故事。

### 公司專項

- **Amazon**：Leadership Principles、無 IDE Coding、Front-End System Design。
- **Binance**：交易產品、WebSocket、即時資料正確性、Web Security、React 深度。
- **台積電**：企業內部系統、穩定性、權限、跨部門需求、長期維護。
- **聯發科**：React / TypeScript、元件架構、測試、CI/CD、RD 生產力工具。

## 每週固定訓練節奏

Google Calendar 的正式訓練時段為週一至週五 20:30～22:50。每天不是只完成一個大主題，而是同時推進演算法、框架與系統設計能力：

| 星期 | 固定內容 | 目的 |
| --- | --- | --- |
| 週一 | NeetCode 150 新題／觀念 60 分鐘＋React 50 分鐘＋收尾 10 分鐘＋System Design Combo 20 分鐘 | 建立新 Pattern，學習本週 React 心智模型，並累積一個系統設計微輸出。 |
| 週二 | NeetCode 150 指定題 60 分鐘＋Python 45 分鐘＋React 回想 15 分鐘＋System Design Combo 20 分鐘 | 練第二題，Python 從基礎逐步走向後端能力。 |
| 週三 | NeetCode 150 閉卷複習 45 分鐘＋React 實戰 60 分鐘＋筆記 15 分鐘＋System Design Combo 20 分鐘 | 把看懂轉成能從空白實作、測試與 Debug。 |
| 週四 | NeetCode 150 指定題 60 分鐘＋Python 實作 50 分鐘＋收尾 10 分鐘＋System Design Combo 20 分鐘 | 完成第三題，並把 Python 觀念轉成可執行程式。 |
| 週五 | NeetCode 150 週測 45 分鐘＋React 面試化／系統設計 45 分鐘＋英文／BQ 20 分鐘＋週檢討 10 分鐘＋System Design Combo 20 分鐘 | 將整週內容轉成面試輸出。 |

週六、日不安排新的固定進度，只用來補完平日行程中明確標記的未完成項目；若本週已完成，就休息或做輕量複習。漏掉一天不把後面 26 週整體順延。

### 三條技術主線

- **NeetCode 150**：每天接觸，依 Arrays / Hashing、Two Pointers、Sliding Window、Stack、Binary Search、Linked List、Trees、Heap、Backtracking、Graphs、DP、Greedy、Intervals、Math / Bit 的順序前進。線性題型較緊湊；Tree、Graph 與 DP 增加畫圖、重寫和複習時間。
- **React（主要框架）**：每週一、三、五，從 Vue 經驗轉換到 React 心智模型，再進入 Hooks 實戰、React Query、realtime、concurrent UI、效能、測試、SSR / Hydration、Next.js 邊界、安全與大型架構。
- **Python（次要能力）**：每週二、四，從 typing、collections、pytest、asyncio 走到 FastAPI、PostgreSQL、SQLAlchemy、認證、Redis、WebSocket、Docker，最後與 React 合成一條可展示的垂直切片。演算法仍先使用熟悉的 JavaScript / TypeScript，避免同時承受新語言與新演算法的負擔。

### 每日 System Design × 高併發 Combo

每天額外用 20 分鐘沿同一個週主題推進，不以「讀過文章」作為完成。每天至少留下架構圖、容量數字、failure case、最小實作或 3 分鐘口述其中一項。

半年順序為：

```text
解題框架與容量估算
  → HTTP / CDN / Load Balancer / 水平擴展
  → Cache / Database / Queue / Consistency
  → Timeout / Retry / Circuit Breaker / Multi-region
  → Frontend Concurrency / WebSocket / Realtime Correctness
  → Security / Observability / Deployment
  → Autocomplete / Feed / Dashboard / Chat / Media
  → Order / Payment / Trading / 企業內部平台
  → Amazon FEE Mock / 四家公司需求變體
```

## 半年路線

### 第 1 個月：重新定位與建立基線

- 整理四家公司的目標職缺與能力矩陣。
- 盤點五年工作中可公開描述的專案、技術決策、事故與量化成果。
- 測試資料結構、演算法、JavaScript、React、英文口說的目前程度。
- 建立演算法資料結構筆記、Pattern 筆記與錯題複習機制。

### 第 2～3 個月：演算法重建與前端深化

- 重新學習 Big-O、Array、Hash、Linked List、Stack、Queue、Heap。
- 由遍歷開始突破 Tree、DFS、BFS 與 Graph，不直接追求題量。
- 深化 JavaScript、TypeScript、Browser、React 與非同步資料流。
- 開始製作一個可公開驗證的 production-grade 前端作品。

### 第 4 個月：系統設計與工程品質

- 練習大型表格、Autocomplete、即時 Dashboard、Design System 等前端系統設計題。
- 補齊效能量測、Testing、Security、CI/CD、Logging、Monitoring 與故障降級。
- 把既有工作經驗整理成 8～10 個可追問的 STAR 故事。

### 第 5 個月：面試化與試投

- 開始做陌生 Easy / Medium 題與限時 Coding。
- 練習不依賴 IDE，並在寫程式時說明思路、Edge Cases 與複雜度。
- 每週進行 Coding、Frontend System Design、專案 Deep Dive 與英文 Mock Interview。
- 先投遞相近公司取得真實面試回饋，再修正準備方向。

### 第 6 個月：四家公司專項衝刺

- 依當期實際 JD 補上公司與團隊專項。
- 完成 Amazon Leadership Principles 故事庫。
- 完成 Binance 交易與即時資料系統設計題。
- 完成台積電、聯發科版本的履歷與企業系統案例。
- 正式投遞四家公司，不因單一公司的招募時程停止其他機會。

## 半年後的驗收標準

### 資料結構與演算法

- Easy 題能在 15～20 分鐘內穩定完成。
- 常見 Medium 題能在 30～35 分鐘內提出合理解法並完成主要程式。
- Tree、BFS、DFS、Graph 基礎題不再完全沒有方向。
- 能說明資料結構選擇、Invariant、Edge Cases 與時間／空間複雜度。

### 前端工程能力

- 能從空白完成中型 React 功能，而不是只看得懂範例。
- 能解釋 render、state、effect、非同步競態與效能取捨。
- 能設計一個包含資料流、錯誤恢復、效能、安全、測試與監控的前端系統。
- 至少有一個可公開查看、可執行、可被追問的工程作品。

### 面試表達

- 能用中文與英文完成自我介紹、專案 Deep Dive 與技術決策說明。
- 準備 8～10 個真實 STAR 故事，並能承受連續追問。
- 能在 Coding 與 System Design 過程中持續說明推理，而不是寫完才解釋。

## 不變的原則

1. 五年工作經驗是優勢，但不能用來跳過基礎考試。
2. 刷題是面試門檻，不是工程能力的全部。
3. 不用完成所有教材才開始投遞，要用真實面試校準準備方向。
4. 不以看完、收藏或題數作為進度；以閉卷重現、陌生題表現、可運行作品與口述能力驗收。
5. 不美化或虛構過往經歷；以可公開的技術範圍、決策、成果與反思呈現價值。

> 這份藍圖是總導航。後續的資料結構、演算法、前端核心、系統設計、行為面試與公司專項筆記，都應能回答：它正在補足哪一項驗收標準？
