# Chapter 08｜DevTools Debugging 與前端節流

讓問題可重現、修正可驗證，並在高流量時維持主要功能。

## 這一章在解決什麼

最後一章把零散技巧變成可重複流程：定義症狀、錄製 trace、找最大瓶頸、修改、驗證，再把結果加入持續監控。尖峰流量時還要讓非核心功能退讓，避免重試風暴。

## 怎麼決定先讀哪一節

若問題是單一操作慢，先錄最小重現；若問題只在流量高時發生，加入請求量、429／5xx、重試與核心任務完成率一起看。

## 本章學習方式

先選一個自己的頁面，照每節的「從頭做一次」保存基準值與操作紀錄。讀完後，把每節的結果連回同一個使用者任務，判斷最大瓶頸是否已經改變。
