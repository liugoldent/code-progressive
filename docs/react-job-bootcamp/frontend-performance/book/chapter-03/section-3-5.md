# 3-5 減輕渲染負擔：Virtualized List

> 學習目標：理解虛擬列表如何減少 DOM，以及動態列高帶來的額外工作。

**核心觀念：** 虛擬列表只建立可視範圍與少量 overscan 的 DOM，適合大量資料造成的 layout、記憶體或更新成本。它與分頁／無限載入解決的是不同問題。

**實作與驗證：** 用 100、1000、10000 筆測初次渲染、捲動幀率與記憶體。加上虛擬化後測動態高度、鍵盤焦點、快速捲動及定位。

**常見誤區：** 資料量不大時引入虛擬化可能增加複雜度而沒有收益。

### 固定高度列表的計算

若每列高 40 px、視窗高 400 px、scrollTop 為 800 px，第一個可見索引約是 `floor(800 / 40) = 20`，可見約 10 列。額外渲染上下各 3 列作 overscan，外層仍保留總高度，內部項目位移到正確位置。

動態列高要在量測後修正位置；此外還要測螢幕閱讀器、鍵盤 Tab、搜尋定位與快速捲動。若 300 筆資料已很流暢，無需因「列表很長」就直接虛擬化。

## 原理拆解

不論資料庫有一萬筆還是十萬筆，畫面同時只能看到有限列。虛擬列表利用這個事實，只建立可視列與少量緩衝列，並用占位高度維持捲動條。固定高度列可直接用捲動位置計算索引；動態高度列需要邊渲染邊量測，可能造成位置修正。若列中的表單、焦點或選取狀態在離開視窗時被卸載，狀態必須保存在列表外或能正確恢復。

## 從頭做一次

1. 先量列表載入、捲動與更新的 frame time、DOM 節點數及記憶體。若 1000 筆都無明顯問題，不要為了「數據多」直接導入虛擬化。
2. 若固定列高，用 scrollTop／rowHeight 算可視起點，渲染視窗加 overscan；若動態列高，加入量測與位置修正，避免捲動跳動。
3. 測快速捲動、鍵盤焦點、螢幕閱讀器、搜尋定位、插入與刪除資料。比較優化前後的首屏時間、幀率與記憶體。

## 如何判斷做對了

只渲染少量 DOM 不代表 API 只抓少量資料；分頁與虛擬列表可併用。

## 書籍逐頁核對｜紙本頁 3-36～3-46

### 3-36～3-38：Windowing 與無限滾動不同

書中先拿社群動態作例子：滾到下方再載入下一批資料屬於資料的延遲載入；如果已載入的 DOM 一直累積，滑到後面仍可能有大量節點。Virtualized List（Windowing）則保留完整清單的邏輯位置，但只渲染可視範圍附近的項目。它主要處理大量 DOM 節點造成的初始渲染、記憶體與滾動成本；不直接解決資料來源的分頁問題。頁 3-38 引用 React 文件和當時可用的 `react-window`、`react-virtualized` 等方案。

### 3-39～3-43：固定高度版本的計算

書中用 React 自製簡化範例，先假設每列高度固定、可視容器高度固定，並讓項目用絕對定位。三個關鍵量：`innerHeight = itemCount × itemHeight` 代表整張清單的總高度；`windowHeight` 代表可見視窗高度；`scrollTop` 是目前滾動位移。接著計算：

```text
startIndex = floor(scrollTop / itemHeight)
endIndex ≈ min(itemCount - 1, floor((scrollTop + windowHeight) / itemHeight))
itemTop = index × itemHeight
```

渲染時外層只佔 `windowHeight` 並可滾動，內層撐到 `innerHeight` 以維持正確捲軸；真正的子項目只建立 `startIndex` 到 `endIndex` 附近的部分，各自放到 `itemTop`。書中用 `renderItem` 回呼交由呼叫端提供列內容。這份公式是固定列高的教學模型；真實產品常須加 overscan，避免快速滾動時露白。

### 3-44～3-46：範例驗證與進階問題

書中用 2,000 筆假資料、每列 40 px、視窗 400 px 示範：畫面一次約看到 10 列，DevTools 中不會有 2,000 個列節點跟著累積。最後列出尚未處理的挑戰：列高不一致需要更複雜的位置計算；快速滾動可預渲染可視區外少量列；容器尺寸可透過 `ResizeObserver` 更新；也可以用 `transform` 調整列位置。書中明確把這個實作定位成理解原理的極簡版，正式需求宜評估成熟函式庫的可及性、動態尺寸、焦點與滾動還原能力。

## 問題與解答：虛擬列表如何省工作

**問題 1：有一萬筆資料，為何不直接渲染一萬個 DOM？** DOM 節點多會增加建立、樣式、layout、更新與記憶體成本。Windowing 只保留視窗可見列及少量緩衝列，滾動時換入內容；資料總量仍可是一萬筆，但 DOM 數維持接近可見範圍。

**問題 2：虛擬列表和無限滾動是否相同？** 不是。無限滾動決定「何時取得下一批資料」；虛擬列表決定「當前 DOM 保留多少列」。兩者可以併用：資料分批取得，已取得資料仍只渲染視窗附近的列。

**問題 3：固定列高時如何決定渲染哪幾列？** 以 `scrollTop / rowHeight` 取整得到起始索引，依容器高度算可見列數，再在前後加 overscan。用上方空白區或位移保留正確滾動高度。列高不固定時需額外量測和更新位置，否則跳動或空白會很明顯。

**問題 4：怎麼知道真的值得虛擬化？** 用 100、1000、10000 筆測初次 render、捲動 frame 與記憶體。若原列表已順暢，加入虛擬化會帶來焦點、鍵盤導覽與動態高度複雜度。修正後也必須測快速捲動與定位到指定列。
