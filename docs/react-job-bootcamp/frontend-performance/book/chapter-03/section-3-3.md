# 3-3 控制 Script 載入時機：Non-Blocking Script

> 學習目標：能根據腳本依賴與 DOM 時機選擇同步、defer、async 或動態匯入。

**核心觀念：** 一般同步 script 可能阻塞 HTML 解析；defer 在解析後按文件順序執行，async 下載完成即執行且順序不保證。module script 通常具備延後執行的載入行為。

**實作與驗證：** 將應用入口與獨立第三方腳本分開，依相依關係選 defer 或 async。看 waterfall 的下載起點、DOMContentLoaded 與主執行緒執行時間。

**常見誤區：** 不要把有順序依賴的腳本全部改成 async；也不要把慢第三方腳本誤認為應用程式的執行成本。

### 腳本選擇表

| 腳本 | 選擇 | 原因 |
| --- | --- | --- |
| 依賴 DOM 與前一個腳本的應用入口 | `defer` | 解析後、按文件順序執行 |
| 完全獨立的統計腳本 | `async` | 不需等待其他腳本，完成下載即執行 |
| 首屏不需要的大型功能 | 動態匯入 | 直到進入功能才下載 |

改動後重看 waterfall 和 DOMContentLoaded。第三方腳本即使 `async`，執行當下仍可佔用主執行緒；因此還要看 Performance trace。

## 原理拆解

同步腳本可能讓 HTML parser 等待下載與執行。`defer` 讓下載與解析並行，解析後依文件順序執行；`async` 也是並行下載，但完成後立即執行，腳本間順序不保證。選擇時先看相依關係，而不是只看哪個關鍵字聽起來較快。即使 async 不擋 HTML 解析，腳本執行仍可與主要繪製競爭主執行緒，所以第三方分析程式常需要再考慮觸發時機與執行成本。

## 從頭做一次

1. 列出腳本與依賴：入口腳本需 DOM 解析完成且與其他腳本有順序關係，可用 defer；獨立統計程式可考慮 async；只在使用者打開功能時才需的模組可動態匯入。
2. 在 Network 看每個腳本開始下載的時間，在 Performance 看執行時是否阻塞主執行緒。檢查 DOMContentLoaded 與 LCP 前的腳本工作是否下降。
3. 在慢網環境測試順序問題，因 async 可能比其他腳本先執行；在低階 CPU 環境測試第三方腳本執行成本。

## 如何判斷做對了

非阻塞下載不等於非阻塞執行：腳本真正執行時仍會競爭主執行緒。

## 書籍逐頁核對｜紙本頁 3-22～3-24

書中先回顧 HTML → DOM、CSS → CSSOM、Layout、Paint 的基本流程，再說明普通 `<script src="...">` 在 HTML 解析途中被遇到時，瀏覽器通常會暫停解析，等待腳本下載與執行。這讓腳本可能進入首屏關鍵路徑。

頁 3-23～3-24 比較兩種不阻塞下載的標註：

- `async`：可與 HTML 解析並行下載；下載完成後盡快執行，執行時會中斷解析。多支腳本的執行先後不保證符合 HTML 中的順序。因此書中以分析工具一類彼此獨立的腳本作使用情境。
- `defer`：同樣可並行下載，但等 HTML 解析完成再執行，且維持原本的腳本順序；適合需要完整 DOM 或相互依賴的腳本。書中也展示動態建立 script 元素的方式，提醒它預設的執行時序需另外留意。

判斷策略時先問腳本是否需要 DOM、是否依賴其他腳本、是否需要在首次畫面前完成。把所有 script 一律加 `async` 可能造成順序錯誤；把重要初始化一律延後也可能讓頁面顯示後無法互動。應以相同頁面的 Network 時序、DOMContentLoaded、LCP 與互動測試驗證。

## 問題與解答：選擇 Script 時機

**問題 1：一般 `<script>`、`defer`、`async` 如何選？** 同步 script 可能停下 HTML 解析；`defer` 可平行下載，待解析完成後依文件順序執行；`async` 下載完成就執行，彼此順序不保證。應用入口或有依賴順序的腳本先考慮 `defer`，獨立統計等腳本才較適合 `async`。

**問題 2：把每支 script 都加 `async` 為何可能壞掉？** 如果 B 依賴 A 先建立全域物件，下載快的 B 可能先執行而報錯。先畫出依賴，再選執行方式；用 Network 看實際下載順序，並測慢網路而非只測本機。

**問題 3：`defer` 是否代表 JS 不會影響首屏？** 不代表。它減少 HTML 解析被同步腳本阻斷的機會，但解析後執行的大型 JS 仍可能佔用主執行緒，延遲繪製或互動。需同時檢查下載與執行時間。

**問題 4：如何驗證調整有效？** 比較修改前後的 DOMContentLoaded、FCP、LCP 與 Main 上的長任務；確認功能和第三方腳本順序正常。若只看到下載提早，執行仍擋住使用者操作，優化仍未完成。
