# Chapter 01｜認識前端效能優化與衡量指標

從使用者感受到的慢開始，選擇正確的量測與診斷工具。

## 這一章在解決什麼

這一章先建立共同語言。先把一次使用者任務拆成等待網路、看到主要內容、第一次操作與畫面穩定四個里程碑，再為每個里程碑選擇工具。Lighthouse 用來產生可重複的實驗室訊號，Performance／Network 用來找原因，真實使用者資料用來檢查改善是否真的發生。

## 怎麼決定先讀哪一節

若畫面晚出現，從 LCP 與資源瀑布開始；若畫面已出現但按鈕卡住，從 INP 與主執行緒開始；若內容跳動，從 CLS 與版面占位開始。

## 本章學習方式

先選一個自己的頁面，照每節的「從頭做一次」保存基準值與操作紀錄。讀完後，把每節的結果連回同一個使用者任務，判斷最大瓶頸是否已經改變。
