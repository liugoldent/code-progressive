# 6-2 WebAssembly

> 學習目標：能公平比較 JS 與 Wasm 的端到端效能，而不是只比計算內核。

**核心觀念：** Wasm 適合已有 C/C++/Rust 核心或大量數值、媒體處理。下載、初始化、資料轉換和跨 JS／Wasm 邊界呼叫都要算入端到端成本。

**實作與驗證：** 為同一演算法設固定輸入，分別量下載、啟動、運算與輸出；與 JS 版本比較小／大輸入。必要時將 Wasm 放入 Worker 保持 UI 流暢。

**常見誤區：** DOM 密集工作不會因改用 Wasm 自動加速。

### 基準測試要納入邊界成本

對 1 KB、1 MB、10 MB 輸入分別量 JS 與 Wasm。記錄模組下載、初始化、資料轉入 Wasm 記憶體、演算法計算、結果轉回 JS 的時間。小輸入可能因初始化與互呼成本使 Wasm 較慢，大輸入才出現收益。

若 Wasm 運算在主執行緒連續執行 500 毫秒，UI 仍可能卡住；與 Worker 結合才能把計算真正移出主執行緒。不要把 Wasm 當成 DOM 渲染加速器。

## 原理拆解

Wasm 適合可隔離、計算密集且常已有原生實作的工作。要比較效能，不能只計運算函式本身；首次下載、編譯／實例化、JS 和 Wasm 間資料轉換、記憶體複製都要算。對很小的資料，這些固定成本可能大於運算收益。Wasm 也不是另一條自動背景執行緒；若在主執行緒執行長運算，UI 仍會卡住，可與 Worker 合併使用。

## 從頭做一次

1. 選擇固定演算法與相同輸入，分別準備小、中、大三種資料量。
2. 拆分量測模組下載、編譯／初始化、資料轉換、運算及結果輸出；使用多次測試和一致設備，避開單次波動。
3. 若運算仍在主執行緒造成長任務，試著與 Worker 結合；並評估套件體積、除錯和維護成本。

## 如何判斷做對了

Wasm 擅長某些可隔離計算，不會直接優化 DOM 或一般商業 UI 邏輯。

## 書籍逐頁核對｜紙本頁 6-11～6-21

### 6-11～6-14：WASM 的定位

書中先比較直譯式 JavaScript 與編譯語言，說明 WebAssembly 是可供瀏覽器執行的二進位指令格式，常由 C、C++、Rust 等語言編譯而來。它讓既有計算程式有機會進入 Web 平台，也可能讓某些 CPU 密集工作更有效率。書中明確強調 WebAssembly 目的是與 JavaScript 合作，不是取代整個前端開發；它不會讓所有程式自動加速。書中列遊戲、圖像與影像處理、數學計算、AR/VR 等可能適用場景。

### 6-14～6-17：AssemblyScript 範例

作者考慮到前端讀者較熟悉 TypeScript，示範用 AssemblyScript 編寫類似 TypeScript 語法的函式，並指出它有自己的型別與支援範圍，不能把任意 TypeScript 專案直接當 AssemblyScript 編譯。書中以斐波那契函式作小範例，建立專案、安裝工具、執行編譯，產生 wasm 檔。目的是看懂編譯與載入流程，而不是用斐波那契微基準斷定 WebAssembly 整體效能。

### 6-18～6-21：載入、快取和 Worker 搭配

書中介紹同步／非同步／串流的 wasm 實例化方式，並以從 `/build/optimized.wasm` 載入後取得 exported 函式的例子說明 JS 與 WASM 的邊界。是否能使用串流方式與 MIME 類型、瀏覽器支援有關，書中列出的相容性是當時狀態，需要現行文件核對。較大的 wasm 模組可評估快取編譯後結果以減少後續啟動成本；書中提到 IndexedDB 作為一種選擇。最後把 WASM 放進 Web Worker 可避免載入／重計算堵住頁面主執行緒，但 JS、Worker、WASM 間的資料傳輸與啟動都有成本，因此不是無條件最佳組合。

## 問題與解答：Wasm 是否值得導入

**問題 1：Wasm 會讓所有前端程式比 JavaScript 快嗎？** 不會。它適合大量數值運算、媒體處理，或重用已有的 C/C++／Rust 核心；DOM 操作仍需透過瀏覽器 API。書中的 AssemblyScript 例子說明編譯與載入流程，不代表每個小函式都會加速。

**問題 2：比較 Wasm 與 JS 時要算哪些成本？** 除了演算法執行，還要算下載、編譯／初始化、資料轉換、JS／Wasm 邊界呼叫及結果輸出。小輸入可能因固定成本而變慢，大量重複運算才可能攤平成本。

**問題 3：Wasm 是否會自動避免頁面卡住？** 不會。若在主執行緒同步執行大量 Wasm，畫面仍可能卡。需要 UI 流暢時可將它放入 Worker，並測主執行緒回應與傳輸資料的成本。

**問題 4：如何建立公平基準測試？** 同一演算法、相同輸入與輸出，分別量首次與重訪、不同資料規模、初始化與純運算時間。功能正確性也要比對；不能只截取 Wasm 核心迴圈忽略載入成本。
