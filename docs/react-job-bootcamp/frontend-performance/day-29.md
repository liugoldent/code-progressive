# Day 29｜高流量時前端能做什麼？

> 本篇是對 2021 年原系列第 29 篇的學習整理，加入現行實務補充；驗證時以你專案的實測結果為準。

**精華：** 前端無法取代後端擴展，但能大幅降低 origin 壓力：CDN 與快取、靜態化、減少重複請求、請求去重、退避重試、載入降級及避免輪詢風暴。

**解答：** 靜態資源與可公開內容交給 CDN；相同 API 請求去重並設短期 cache；失敗重試採 exponential backoff 加 jitter，避免所有客戶同時重打。關閉非核心功能、降低圖片品質或更新頻率，保住登入、搜尋、結帳等主流程。

**實務：** 設計 graceful degradation；非核心圖片、推薦、動畫或第三方服務失敗時，主要流程仍應可用。

## 深入理解

流量尖峰時，前端可減少重複請求與非必要工作，並讓主要流程先成功。快取、請求去重、限制並行和退避可降低 origin 壓力，但全站容量仍需後端與基礎設施一起設計。

## 實作與驗證

列出登入、搜尋、付款等核心流程及可關閉的推薦、分析、動畫。對可快取的公開資料設定 CDN；對同鍵 API 去重；重試採上限、指數退避與 jitter。演練 429、5xx 和第三方超時時的 UI。

## 常見誤區與取捨

不要對失敗請求無上限立即重試，否則尖峰時形成重試風暴。付款等非冪等操作需更嚴格處理重複提交。
