# Day 25｜Edge-side Rendering

> 本篇是對 2021 年原系列第 25 篇的學習整理，加入現行實務補充；驗證時以你專案的實測結果為準。

**精華：** 把渲染或部分計算移到靠近使用者的 edge，可縮短伺服器回應等待並保留動態內容能力。

**解答：** 適合在 edge 做地區導向、A/B 判斷、輕量個人化與可快取頁面渲染；資料也應在附近或有快取。先測端到端 TTFB，若每次仍需跨洲查主資料庫，應先改善資料位置與快取。

**取捨：** Edge runtime 有 API、執行時間、套件及資料存取限制；若資料庫仍在遙遠區域，渲染搬到 edge 不一定改善整體延遲。

## 深入理解

Edge rendering 將部分運算移近使用者，但端到端延遲還包括資料庫、API、第三方服務和快取。若資料仍在單一遠端區域，每次跨區讀取可能吃掉地理收益。

## 實作與驗證

把 TTFB 拆成 edge 啟動、資料取得、渲染和回傳；用不同地區、冷／熱快取比較。先處理可快取內容或輕量地區化，再考慮完整邊緣渲染。

## 常見誤區與取捨

Edge runtime 的 Node API、封包大小、CPU、網路與部署限制會因供應商而異，架構決策需對照實際平台。
