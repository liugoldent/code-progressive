# Day 02｜為什麼前端需要效能優化？

> 本篇是對 2021 年原系列第 2 篇的學習整理，加入現行實務補充；驗證時以你專案的實測結果為準。

**精華：** 速度直接影響使用者體驗、留存、轉換與搜尋能見度。開發者的高階設備與網路容易掩蓋真實使用者的困境。

**解答：** 把效能寫成可驗收需求，例如限制首屏資源量、互動延遲與版面位移；測試時使用低階裝置、網路節流與冷快取，並蒐集真實使用者指標。這能避免只在開發者電腦上「感覺很快」。

**實務：** 測試時納入低階手機、慢速網路、冷快取及真實地區；將效能設為產品需求，而不是上線後才處理的美化工作。

## 深入理解

效能問題會讓使用者等待、誤觸、重複提交或放棄任務。慢速裝置特別容易被大量 JavaScript 的解析與執行拖累，因此下載大小只是成本的一部分。

## 實作與驗證

將產品目標寫成『某頁某操作在某設備與網路下的 p75 指標』，並分行動版／桌面版、地區、頁面與登入狀態觀察。記錄成功率、錯誤率和效能指標，避免只優化表面速度。

## 常見誤區與取捨

模擬慢速網路不等於模擬低階 CPU；只在開發機上節流，仍可能低估真實裝置的計算與記憶體壓力。
