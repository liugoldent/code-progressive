# Day 23｜WebAssembly

> 本篇是對 2021 年原系列第 23 篇的學習整理，加入現行實務補充；驗證時以你專案的實測結果為準。

**精華：** WebAssembly 提供緊湊的二進位格式與接近原生的執行能力，適合把既有 C/C++/Rust 或計算密集模組帶到 Web。

**解答：** 只將可隔離且計算密集的核心（編解碼、影像、壓縮、科學運算）編譯成 Wasm，UI 與 DOM 協調留在 JavaScript。先基準測試 JS 版本，再計入模組下載、初始化與跨邊界呼叫成本比較。

**取捨：** DOM 密集、一般商業邏輯不會因改成 Wasm 自動變快；JS/Wasm 邊界、下載、初始化與除錯都有成本。

## 深入理解

Wasm 以二進位模組執行計算，常用於影像、音訊、編解碼與既有原生演算法。效能收益取決於演算法、記憶體表示與 JS/Wasm 互呼次數。

## 實作與驗證

用相同輸入和裝置，分別量測下載、compile/instantiate、資料轉換、運算及結果輸出時間。只搬一個純計算核心做原型，並測小輸入與大輸入的交會點。

## 常見誤區與取捨

Wasm 無法直接讓 DOM 操作變快，也不天然避免主執行緒卡頓；長時間 Wasm 運算仍可放進 Worker。
