# Day 01｜系列地圖

> 本篇是對 2021 年原系列第 1 篇的學習整理，加入現行實務補充；驗證時以你專案的實測結果為準。

**精華：** 效能優化涵蓋資源體積、網路、瀏覽器渲染、JavaScript 執行、快取及架構。不要一開始便隨機套技巧，應先建立整體地圖。

**解答：** 採用固定流程：先以 Lighthouse、Performance panel 與真實使用者資料建立 baseline，再從傳輸、載入、渲染、執行、快取五層找最大瓶頸。一次只改一個變因，重新量測後才保留修改。

**複習：** 任何優化都要能回答：改善哪個指標、犧牲什麼、如何驗證？

## 深入理解

先畫出一次導覽的時間線：DNS／連線、TTFB、HTML 解析、關鍵資源下載、主執行緒執行、繪製及互動。每段慢的原因不同；傳輸量小也可能因伺服器等待或 JavaScript 長任務而慢。

## 實作與驗證

選一個最常用頁面，記錄裝置、網路、冷／熱快取與登入狀態。保留 Network waterfall、Performance trace 和 LCP／INP／CLS 基準值。接著只改一項因素，再用相同條件重測。

## 常見誤區與取捨

不能只用首頁代表整站；搜尋、列表、詳情和結帳各有不同瓶頸。總分上升也不代表主要使用路徑改善。
