## 十六章反覆出現的問題

每題最後都會回到六件事：**需求到底是什麼、權威資料在哪、讀寫資料怎麼走、重試會不會重複、故障時會遺失什麼、如何證明方案有效**。元件名稱是次要的。若架構圖裡有 Redis、佇列、CDN、分片與多區，卻說不出每個元件失效後的行為，方案仍不完整。

## 一張跨題檢查表

| 檢查面向 | 要能回答 |
| --- | --- |
| 需求 | 核心操作、明確不做的功能、使用者可接受的延遲 |
| 規模 | 平均與尖峰 QPS、熱 key、單筆大小、保留期、同時連線 |
| 資料 | 權威儲存、索引、版本、備份、刪除與撤銷 |
| 一致性 | 哪些讀可舊、哪些寫不可重複、衝突如何處理 |
| 可用性 | 節點/區域/供應商故障、回復時間、降級方案 |
| 安全 | 身分、授權、濫用、私有資料在快取中的生效窗口 |
| 觀測 | p95/p99、錯誤率、積壓、複寫落後、成本與資料核對 |

這張表不是每題都要講一樣久。影音題多花時間在媒體位元組、轉碼和 CDN；聊天題在順序、回執與離線同步；雲端硬碟在版本與衝突。先辨認題目最有辨識度的難點，再套用共通檢查。

## 從面試圖走到小型實作

可以挑一題做最小版本，例如短網址：先做資料庫唯一索引與跳轉，加入 idempotency key，再加快取與過期，最後用壓測製造熱門短碼。每加一步，記錄 p95、錯誤率、資料庫 QPS 與成本。或者做通知系統：用同一資料庫交易寫業務資料和 outbox，故意在 relay 的不同位置讓程序當機，觀察重複與補償。

實作不必重現大廠規模。小型可運行系統更能幫你看見「理論上會重試」具體是怎樣的失敗；壓測與故障注入能讓設計假設變得可驗證。

## 最後一次閉卷練習

選一題未在本書中的產品，例如活動預約、多人共同編輯或圖片轉檔服務。限時 45 分鐘：前 8 分鐘問需求與估算，中間 12 分鐘畫高階方案，接著 20 分鐘深入一個難點，最後 5 分鐘說故障、監控與取捨。完成後用上表檢查遺漏。若能以相同方法解新題，這組筆記才真正變成你的能力。
