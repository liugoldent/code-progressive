# 前言｜如何使用第一輯筆記

> 原書前言：v–vi 頁，已依閱讀器核對。這是本站寫給讀者的導讀，**不是原書前言的重述**。

原書前言先談系統設計面試沒有唯一標準答案，重點在合作釐清問題、理解取捨與逐步建立能力。本站據此把筆記做成「先提出假設，再推導資料流與故障」的練習材料；後面的具體 API、SLO 和範例數字仍屬本站延伸。

## 這組筆記要幫你練什麼

系統設計不是記住某道題的最終架構圖，而是能從需求、負載與失敗條件推導設計。第一輯的 16 章可分為三段：前 3 章建立規模與面試方法；第 4–7 章練限流、分片、儲存和 ID；第 8–15 章把共通模式放進不同產品；第 16 章練遷移與反思。

本筆記按[原書目錄](/docs/system-design/system-design-interview-reading-map)逐章排列。每章都盡量回答：要先問什麼、最小可行方案是什麼、資料如何流動、哪裡會壞、為何選這個方案，以及怎麼練。若是面試準備，建議先自己畫 10 分鐘，再看該章，避免變成只熟悉別人的圖。

## 讀書時的四種標記

1. **書中主題：** 章名、題目範圍與原書起始頁以目錄為準。
2. **本站延伸：** 範例 API、容量數字、資料模型、故障演練和部分產品選項是重新設計的練習材料。
3. **待驗證事實：** 具體資料庫、雲端服務或 HTTP 行為應再查官方文件；版本與實作會改變。
4. **自己的假設：** 實際工作中應用流量、SLO、使用者行為、成本和法規重新決定方案。

## 每章怎麼讀

先只看章題，在紙上寫 3 個功能問題、3 個非功能問題、估算式和一條成功資料流。閱讀本章筆記後，把不一樣的地方圈起來，回答「是哪個需求或假設讓方案改變？」最後用章末自測閉卷說一遍。若答不出，優先補足那個概念，再繼續下一章。

例子：讀「短網址」前先決定目的地可否修改。若可修改，`301` 永久快取可能不合適；若不可修改且跳轉流量巨大，快取策略又可以更積極。兩個方案不同，不一定有誰錯，而是約束不同。

## 記下真正不會的地方

筆記卡可以只放六行：題目、需求假設、畫出的資料流、最不確定的一步、故障時的使用者現象、下次要查的資料。不要把整頁文字再抄一次。能從空白推導出方案，才算掌握。
