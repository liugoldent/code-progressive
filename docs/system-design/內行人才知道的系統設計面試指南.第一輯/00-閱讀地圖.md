# 第一輯閱讀地圖｜依原書章節順序

本資料夾依 Alex Xu 著、藍子軒譯《內行人才知道的系統設計面試指南》第一輯編排。章名與起始頁依你提供的目錄截圖核對；也對照了 [HyRead 館藏](https://tycccgov.ebook.hyread.com.tw/bookDetail.jsp?id=277385)與閱讀器目次。已按閱讀器順序核對前言、正文第 1–313 頁，以及書末版權與封底；各章開頭提供**逐頁閱讀線索**，方便回查。各章還有**自測參考解答與面試追問**，把原本只列題目的部分補成能核算、能推演故障與說明取捨的答案。筆記以自己的話重組概念、補充例子，沒有重製原書圖表或長篇原文。書中未必使用筆記中的 API、數字或實作取捨，閱讀時請把兩者區分。

## 建議閱讀順序

1. 讀[前言筆記](/docs/system-design/volume-1/preface)，了解這組筆記如何使用。
2. Chapter 1–3 建立規模估算與面試表達；Chapter 4–7 練分散式基礎。
3. Chapter 8–15 逐題畫成功路徑與故障路徑；每題先自己作答，再看筆記。
4. Chapter 16 與後記把案例變成可遷移的設計方法。每週挑一題閉卷重畫。

## 每讀完一章，做一次四步練習

1. **閉卷畫圖：** 只看題目寫核心需求、權威資料、讀寫路徑。
2. **估三個數字：** 尖峰 QPS、主要資料量，以及最可能吃掉成本的資源。
3. **插入一個故障：** 在兩個步驟之間當機，說出使用者現象、資料風險和恢復方式。
4. **改一個約束：** 使用者十倍、跨區、離線、嚴格撤權或成本減半，說出原方案哪裡先失效。

先做自己的版本，再對照筆記與原書。若兩者方案不同，優先比較需求、規模、SLO 與故障承諾，不要只比元件清單。其他相關筆記：[高流量網站架構](/docs/system-design/high-traffic-web-architecture)、[Redis 與 Cache 入門](/docs/system-design/redis-cache-react-python)。

閱讀章末問答時，可先遮住答案口述一次，再對照三件事：**是否把需求前提說清、是否算出量級、是否指出失敗後的可觀察結果**。問答中的範例數值與資料模型是本站為練習而設，不代表書中唯一答案。

- [作者對第一輯與第二輯的定位](https://blog.bytebytego.com/p/system-design-interview-books-volume)。
- 筆記中所有容量範例都是**示意假設**，不是原書基準值或生產環境建議。落地前要以真實流量、SLO、供應商限制與成本重新計算。
