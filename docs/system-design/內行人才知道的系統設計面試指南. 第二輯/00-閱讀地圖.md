# 《內行人才知道的系統設計面試指南. 第二輯》閱讀地圖

這份筆記依 Alex Xu、Sahn Lam 的第二輯十三個章節主題安排。我已用 HyRead 閱讀器依序翻閱十三章正文，將相鄰頁的關鍵推導濃縮在各章末尾的「原書逐頁核對」節。那是**按閱讀順序整理的重點與自學問題**，不是原文轉錄；圖、表、完整例子與作者的細節仍請在原書查看。

每章前半部是本站先寫的**自行推導與延伸練習**，包含不少自行設定的需求、數字和工程方案，不應當成原書結論。自學時可先做前半部手算與故障推演，再讀章末的原書重點，最後回到書中核對圖解。頁碼以閱讀器顯示位置作章內導覽；不同版本的印刷頁碼可能不同。

依照自學需求，每章的原書重點後方另有「自學問答」，直接解釋設計理由、失敗情境、手算與方案取捨。問答是依章節主題撰寫的教學解說，部分包含本站自行補充的例子；它們幫助你理解原理，仍應搭配原書圖表閱讀。

## 每章都用同一套檢查法

1. **界定範圍**：主要使用者、讀寫操作、延遲目標、一致性與資料保留。
2. **抓量級**：平均與尖峰 QPS、資料大小、熱點和扇出。所有估算寫清單位與假設。
3. **畫最小流程**：API、資料模型、資料流，以及哪個元件持有真實來源。
4. **找最先爆的點**：單鍵熱點、跨區同步、外部依賴、雙寫、順序或儲存成本。
5. **說明失敗語意**：逾時但成功、重試、重複事件、落後資料、部分故障和復原。
6. **驗證**：列出 p95/p99、錯誤率、積壓量、資料正確性與成本指標。

## 建議練法

如果你是第一次學系統設計，請先讀[自學先備概念與解題方法](./00a-自學先備概念.md)，完成其中四題自我檢查，再依上表順序讀十三章。每讀一章先遮住後半篇，自己回答需求和最小資料流，再對照筆記。讀完後做[十三章練習題與參考解答](/docs/system-design/內行人才知道的系統設計面試指南.%20第二輯/自學練習與解答)，隔天不看答案重做一次。

遇到章末問答時，先只看題目，寫出自己的資料流和失敗處理，再讀解答。若答案用到 QPS、儲存量或時間窗，請重新計算一次並寫明單位與假設；若答案用到 Redis、Kafka、資料庫等工具，請說出它在該流程中負責哪一件事，而不是只記工具名稱。

每題可用 5 分鐘寫需求、10 分鐘做高層設計、15 分鐘深入一個瓶頸、5 分鐘檢查故障與取捨。開始時不必追求面試速度；先能用自己的話解釋每個元件為何存在。完成一章的標準是：能畫出資料流、手算一個小例子、說清至少一個當機點的復原方式，並指出哪份資料是真實來源。

### 四週自學安排

| 週 | 內容 | 學完要交出的成果 |
| --- | --- | --- |
| 1 | 先備概念、1–3 章 | 三種地理查詢的資料流與邊界案例 |
| 2 | 4–6 章 | 一次訊息重播、時間窗口修正和警報規則的手算 |
| 3 | 7–10 章 | 訂房併發、投遞未知狀態、物件寫入、榜單結算的時序圖 |
| 4 | 11–13 章與總複習 | 付款與錢包對帳表、交易所撮合手算、三題口述錄音 |

每週最後挑一題用 30–45 分鐘口述，錄下來檢查是否有先定義需求、數字是否有單位、是否把逾時錯認成失敗、是否有說明成本與觀測方式。

十三章做完後，讀[跨章設計取捨與故障對照](/docs/system-design/內行人才知道的系統設計面試指南.%20第二輯/跨章設計取捨)，把資料來源、故障與一致性要求從各章抽出來比較，再練習一題書外題目。
